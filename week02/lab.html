Week 2 Lab — CyberCorp Passive OSINT Dossier (Project Phase 1)

Build a reproducible passive footprinting dossier for the fictional client CyberCorp Enterprise using only free tools and authorized targets. This is the CEH footprinting deliverable that feeds Week 3 scanning.

⏱ About 2.5 hours🧰 Kali or any Linux · dig/whois/RDAP · exiftool · browser📦 Simulated CyberCorp pack in lab-assets/✅ Solutions included
Lab parts Before you start Part 0 — Ethics gate (10) Part 1 — Domain & DNS (25) Part 2 — Website files (25) Part 3 — Metadata (25) Part 4 — People & tech (25) Part 5 — Dorks on paper (20) Part 6 — Dossier & countermeasures (30) Resources

Before you start

Goal. Produce dossier.md (or PDF) with dated, sourced CyberCorp findings across organization, network, system and people baskets, plus countermeasure recommendations.
Ethics. Passive OSINT only. Authorized targets: the fictional CyberCorp files in lab-assets/, example.com, scanme.nmap.org, and your own systems. Do not dork, scan or scrape real organizations, classmates, workplaces or the college network. Generative AI is allowed to help clarify concepts if cited, but is prohibited on Quiz 1.
Checkpoint files. dossier.md, command log, copies of exiftool output, and a short countermeasures list.

Create a working folder:

mkdir -p ~/cybercorp-phase1 && cd ~/cybercorp-phase1
cp -r /path/to/week02/lab-assets ./

Part 0 — Ethics gate (10 min)

Confirm you can state the authorization boundary before any tool runs.
  • Write four bullets: in-scope targets, out-of-scope examples, what “passive” means today, and what you will do if you accidentally find real credentials on the public web.
  • Paste those bullets at the top of dossier.md.
Show solution

In scope: CyberCorp simulated pack; example.com; scanme.nmap.org; own VMs.

Out of scope: real local businesses, college network, classmates’ hosts, random GHDB targets.

Passive: public pages, registries, archives, CT logs, files already published / provided — no probes to CyberCorp servers, no social engineering.

If real credentials appear: stop, do not use them, do not share them, tell the instructor, preserve evidence if asked.

Part 1 — Domain & DNS on example.com (25 min)

Practise RDAP/WHOIS and DNS reads on the permitted domain example.com, then copy the skill onto the simulated CyberCorp domain card.
  • Look up example.com via ICANN Lookup or whois example.com / RDAP. Record registrar, dates, NS, DNSSEC.
  • Resolve A, AAAA, NS, MX, TXT, SOA (dig or a DoH client). Note the null MX if present.
  • Resolve scanme.nmap.org A and its PTR.
  • In the dossier, create a CyberCorp domain table using the simulated values from lecture (ns1/ns2.cybercorp.example, portal/staging/vpn/mail).

Part 2 — Website files (25 min)

Extract attack-surface hints from robots.txt and sitemap.xml without touching a live CyberCorp server.
  • Open lab-assets/cybercorp-site/robots.txt and list every Disallow path. Explain why robots.txt is not access control (RFC 9309).
  • Open sitemap.xml and list URLs that look like staging, portal, or document paths.
  • Optional: visit web.archive.org for example.com and note the earliest capture year you see.
Show solution

Paths of interest: /admin/, /backup/, /old-portal/, /hr/onboarding-2026/, /dev/. Sitemap adds careers, press, VPN PDF, portal.cybercorp.example, staging.cybercorp.example. RFC 9309: rules are not authorization; listing paths discloses them.

Part 6 — Assemble dossier & countermeasures (30 min)

Produce the Phase 1 deliverable.
  • Write a ½-page executive summary for CyberCorp’s CIO.
  • Include tables: domain/DNS, subdomains, people/emails, technologies, web paths, metadata findings.
  • Add 5 concrete countermeasures (metadata scrubbing, job-ad review, CT monitoring, robots≠ACL, staging DNS hygiene).
  • Appendix: commands run + dates.
Show solution (outline)

Exec summary: Passive review of CyberCorp’s public trail shows VPN and portal technologies, staging exposure, internal UNC paths in a published guide, and a predictable email pattern. No active scans were performed. Priority fixes: scrub metadata, restrict staging certificates/DNS, rewrite job posts, treat robots Disallow paths as disclosure.

Countermeasures: (1) exiftool scrub on all press/docs; (2) HR job-ad tech review; (3) monitor crt.sh / CT; (4) authenticate /admin and /backup; (5) remove staging from public DNS when idle.
